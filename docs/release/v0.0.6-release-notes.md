# Fornax v0.0.6 — Enterprise Policy & Fleet Governance

**Status:** Real, complete release. Full QA/security evidence:
[`docs/release/v0.0.6-qa-signoff.md`](v0.0.6-qa-signoff.md). Candidate
manifest: [`release/v0.0.6-candidate-manifest.json`](../../release/v0.0.6-candidate-manifest.json).

## What this is

Fornax v0.0.6 adds enterprise policy authoring and fleet governance on top
of v0.0.5's causal/longitudinal verification layer:

- **Signed policy authoring & distribution** — versioned policy-as-data
  contracts, cryptographically signed and domain-separated bundles.
- **Local verified cache** — offline devices continue on documented
  last-known-good semantics; a rollback-safe sequence high-water mark
  prevents replaying a stale valid bundle.
- **Staged rollout & rollback** — target a canary cohort, roll back or
  supersede, observe fleet-wide convergence.
- **Signed revocation lists** — sticky, replay-resistant; a revoked bundle
  can never be silently un-revoked by an old list replay.
- **Fleet health** — active/stale/degraded policy state visibility across
  enrolled devices.
- **Risk-classified enforcement** — fail-open/fail-closed behavior by
  action/risk class, closed by construction against an unrecognized risk
  tier.

## This is a real, complete release

Unlike v0.0.4 and v0.0.5's Developer Preview framing, Stage 6b's release
gate — [FORNX-124](https://lightning-dust-mite.atlassian.net/browse/FORNX-124),
[POLICY & FLEET READY] — is genuinely earned. It was closed with real,
live, end-to-end cross-repo verification: real Postgres, a real fornax-cloud
server, real fornax-daemon processes, real signed artifacts, real HTTP poll
cycles. That process found and fixed one real Critical defect
(a wire-contract mismatch between fornax-cloud and fornax-core over policy
revocation) before re-verifying live. There is no unfabricatable
external-evidence gap here, unlike v0.0.4/v0.0.5's calibration-data
blockers.

## Security

A fresh, independent review — separate from FORNX-124's own live-verification
pass — covered signature verification, sequence-based rollback/replay
resistance, revocation-list integrity and replay resistance, fail-closed
risk enforcement, rollout-targeting injection surface, and resource
exhaustion. **Zero findings.** `risk_class: TRUST_BOUNDARY` reflects the
stakes of a new cryptographic bundle-verification trust boundary gating
real device behavior, not any defect. See
[`docs/release/v0.0.6-qa-signoff.md`](v0.0.6-qa-signoff.md) for full detail.

## Cross-repo pairing

This release's device-side policy consumer pairs with
[fornax-cloud v0.0.3](https://github.com/horonomy/fornax-cloud/releases/tag/v0.0.3%2Bcorrected.f1b293c),
which ships the cloud-side policy authoring, rollout, bundle-distribution,
and revocation endpoints. Both halves of this capability are now formally
released.

## Migration notes

No breaking changes to existing `Evidence`, `Finding`, `Fusion`, causal/
replay, or CLI/API contracts. All new surfaces (policy bundle, cache,
rollout, revocation, fleet health) are additive.
