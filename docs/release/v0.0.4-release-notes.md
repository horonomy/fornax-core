# Fornax v0.0.4 — Multi-Signal Integrity Engine (Developer Preview) — Release Notes

**Status:** DEVELOPER PREVIEW / PRERELEASE. Founder-authorized 2026-09-24
scoped release: ships the verified 6/7 Stage-4 engineering scope. Does
**not** claim the full [MULTI-SIGNAL READY] gate (FORNX-97) is satisfied —
see "What this is not" below. Full evidence:
[`docs/release/v0.0.4-qa-signoff.md`](v0.0.4-qa-signoff.md). Candidate
manifest: [`release/v0.0.4-candidate-manifest.json`](../../release/v0.0.4-candidate-manifest.json).

## What this is

Fornax v0.0.4 begins evolving Fornax from deterministic claim checks into
a multi-signal integrity system: an inspectable evidence graph, additional
independent evidence sources beyond the coding agent's own self-report,
explicit evidence-quality metadata, a fusion engine that combines
heterogeneous evidence with visible uncertainty, an optional local
semantic judge, and a decision layer (PROCEED/REVIEW/BLOCK) that explains
its own rationale rather than hiding behind an opaque score.

## What's included (all Done, engineering-complete)

- **Evidence Graph** (FORNX-89): claims linked to supporting/contradicting/
  missing evidence with explicit provenance; missing evidence modeled, not
  inferred from empty arrays.
- **Evidence Explorer** (FORNX-90): local/SaaS UI to inspect the evidence
  graph behind a finding, including missing/unavailable/correlated
  evidence.
- **Independent Sensors** (FORNX-91): two new evidence sources beyond the
  agent's own tool-call self-report — `fornax-vcs` (git-native
  working-tree/commit evidence) and `fornax-ci` (GitHub CI-status
  evidence).
- **Evidence Quality** (FORNX-92): freshness/expiry, trust class,
  dependence/correlation grouping so two model-authored signals aren't
  double-counted as independent.
- **Fusion Engine** (FORNX-93): combines evidence with explicit
  uncertainty; reproducible for a pinned policy/version; missing/failed
  sensors never silently treated as negative evidence.
- **Semantic Judge** (FORNX-94): an optional local, self-hosted LLM-judge
  evidence source — one signal among many, never the sole verifier, always
  labeled model-derived.
- **Decision UX** (FORNX-96): PROCEED/REVIEW/BLOCK recommendation with
  visible rationale, distinct from the underlying Finding/evidence graph.

## What this is not

**Not a proven multi-signal effectiveness claim.** FORNX-97
([MULTI-SIGNAL READY]) — "at least one multi-signal configuration
demonstrates meaningful operational improvement over baseline under
predeclared metrics" — remains **open and deferred, not satisfied, not
waived**. The calibration/ablation harness that would measure this
(FORNX-95, `fornax-bench`) is itself engineering-complete — real
reproducible manifests, fixed-risk metrics, per-sensor ablation — but has
only ever been exercised against synthetic fixtures, which by design
cannot demonstrate real-world value. No human-adjudicated labeled
integrity-outcome dataset currently exists to run that study against, and
this release does not fabricate, lower the bar for, or substitute
synthetic data for that requirement. This gap was escalated as a genuine
research/product decision on 2026-09-05 and reconfirmed on 2026-09-24
rather than silently resolved.

**If you enable the Semantic Judge or additional sensors in this
release**, treat their output as additional inspectable evidence, not as
a calibrated confidence signal — Fornax does not yet have real evidence
that combining these signals improves decision quality over the v0.0.1
deterministic baseline.

## Path to the real calibration claim

[FORNX-343](https://lightning-dust-mite.atlassian.net/browse/FORNX-343)
(Stage 8, "Gold Corpus Bootstrap") is the existing path toward a real
human-adjudicated dataset — it requires genuine human review
([FORNX-342](https://lightning-dust-mite.atlassian.net/browse/FORNX-342),
"Corpus Adjudication"), which this release does not attempt to
substitute for. FORNX-97 is linked in Jira as blocked by FORNX-343.

## Security

Real security/privacy review performed on the three new sensors (see
[`docs/release/v0.0.4-qa-signoff.md`](v0.0.4-qa-signoff.md) for detail).
One Medium finding (a verdict-inversion bug in the Semantic Judge's
response parser) and one Low finding (a redact-before-truncate ordering
defect in the same module), both found and fixed within this pass with
real regression tests. No Critical/High finding.

## Migration notes

No breaking changes to `Evidence`, `Finding`, or existing CLI/API
contracts. All new surfaces (Evidence Graph queries, Fusion Engine,
Semantic Judge, Decision UX) are additive.
