## What this does NOT cover — and does not claim

**FORNX-97 [MULTI-SIGNAL READY] remains open, not passed, not waived.**
Its AC requires "at least one multi-signal configuration demonstrates
meaningful operational improvement over baseline under predeclared
metrics," measured against a real human-adjudicated labeled dataset. That
dataset does not exist. `fornax-bench` (FORNX-95) is engineering-complete
— reproducible manifest, fixed-risk metrics, per-sensor ablation, honest
`Option<f64>` rates that never fabricate a result — but has only ever been
exercised against synthetic fixtures, which by design produce zero real
findings about real-world value.

This was escalated rather than auto-resolved on 2026-09-05 ("fabricating
this unilaterally risks producing a self-validating false 'proof of
value' for the exact kind of claim Fornax exists to keep honest") and
reconfirmed on 2026-09-24. The founder explicitly authorized shipping the
completed 6/7 scope as a **Developer Preview** instead, with this gap
stated plainly rather than glossed over.

**Follow-up path (linked, not duplicated):** [FORNX-343](https://lightning-dust-mite.atlassian.net/browse/FORNX-343)
(Stage 8, "Gold Corpus Bootstrap") is the existing, reused path toward
eventually producing a real human-adjudicated dataset — it requires real
human review (FORNX-342, "Corpus Adjudication"), which this pass does not
attempt to substitute for. FORNX-97 is linked as "is blocked by" FORNX-343
in Jira.

## Security review

Real, already-performed (FORNX-97's own gate-procedure item, 2026-09-02):
privacy/security review of the three sensors merged this Stage-4 pass
(git-native working-tree evidence, GitHub CI-status evidence, local
self-hosted Semantic Judge). Full findings and adversarial-coverage
detail: [`release/v0.0.4-security-signoff.json`](../../release/v0.0.4-security-signoff.json),
[`release/v0.0.4-trust-boundary-delta.json`](../../release/v0.0.4-trust-boundary-delta.json).

Summary — one Medium, one Low, both fixed with real regression tests
(commit `27d25f0`, before this candidate's freeze SHA), one informational
accepted-risk item (new sensors apply pre-existing untrusted-input
patterns, not a new exposure class):

- **SEC-v0.0.4-0001 (Medium, fixed):** the Semantic Judge's response
  parser could invert a negated model verdict ("UNSUPPORTED"/"NOT
  SUPPORTED" both contain the substring "SUPPORTED") to `Supported` — the
  opposite of what the model said. Fixed; regression test
  `parse_model_response_does_not_invert_a_negated_supported_reply`.
- **SEC-v0.0.4-0002 (Low, fixed):** the judge's evidence-summary path
  truncated before redacting, so a secret straddling the 200-char cut
  could survive with only a sub-detection-threshold prefix exposed to the
  redactor. Fixed (redact-then-truncate); regression test
  `evidence_payload_summary_redacts_a_secret_that_straddles_the_truncation_boundary`.

No Critical/High finding. `risk_class: TRUST_BOUNDARY` (new
`adapter_provider_input`/`evidence_provenance`/`egress_redaction` surface
touched by the new sensors and judge).
