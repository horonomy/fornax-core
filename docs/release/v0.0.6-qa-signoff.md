## Fresh, independent security/QA review (this release, 2026-09-24)

A separate pass — not re-litigating FORNX-124's findings — reviewed:

1. **Signature verification correctness** — strict-canonical decode, domain
   separation, `verify_strict`, fail-closed on unrecognized algorithm. No
   findings.
2. **Rollback/replay via bundle sequence** — closed at the cache layer via
   a persisted high-water mark (`SequenceNotAdvanced`, `SequenceReused`).
   Tested: `cache_tests.rs:336,414`. No findings.
3. **Revocation-list integrity/replay** — sticky/union-only, own high-water
   mark blocks old-list replay. Tested: `revocation_tests.rs:352`. No
   findings.
4. **Revocation precedence** — checked first in `evaluate_activation`,
   before lineage/sequence. No findings.
5. **Fail-open/fail-closed risk enforcement** — closed enum, no permissive
   fallback. No findings.
6. **Rollout targeting** — matches locally-established device identity, not
   attacker-suppliable wire data. No findings.
7. **Resource exhaustion** — `MAX_PAYLOAD_BYTES` (1MB), `MAX_SIGNATURES`
   (8), `MAX_REVOCATION_ENTRIES` (4096) bound all pre-authentication input;
   flat rule structure eliminates combinatorial-explosion risk. No
   findings.
