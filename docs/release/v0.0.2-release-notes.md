## What this is

Fornax v0.0.2 turns the locally-proven v0.0.1 vertical slice into the
backend and API surface for a real Internet-facing Beta product, without
weakening the local-first trust boundary: raw evidence stays local by
default, upload is policy-controlled and redacted before it ever leaves
the machine, and the local hot path never requires cloud access.

This release is about **fornax-cloud** (the companion cloud-side repo) far
more than fornax-core. fornax-core has no v0.0.2-specific scope — the
v0.0.2 candidate pins it at the same commit as v0.0.1.

## What's included (fornax-cloud)

- **Device onboarding** (FORNX-150/151): self-service device
  register/rotate/revoke over HTTP, least-privilege ingest credentials, a
  device list with self-reported and empirically-observed capability
  metadata. See fornax-cloud's `README.md` "Beta device onboarding" section
  for the exact API contract.
- **Authenticated ingest hardening** (FORNX-75/282): the ingest gateway
  requires a valid device credential; uploader token failures fail fast
  instead of silently quarantining every item (FORNX-283).
- **Beta observability** (FORNX-77/153): structured logging reaching
  stdout correctly, alerting groundwork for Cloud Run/Pub/Sub/DB.
  Diagnosable-from-telemetry failure modes, no raw payloads in operational
  logs.
- **Privacy fixtures and migration coverage** (FORNX-79/78): local privacy
  fixtures for redaction testing; migration tests covering both fresh and
  previous-schema Alembic states.
- **Evidence Explorer + decision UX (SaaS)** (FORNX-301/303/305):
  capability-driven frontend/backend split, evidence explorer, decision UX
  for the hosted dashboard.
- **Reliability fixes**: pub/sub device-check hardening, sensitive-path
  redaction (FORNX-284/286), accepted-counter no-op conflict fix
  (FORNX-58), LRU cache settings leak fix (FORNX-294), backend startup
  without Application Default Credentials (FORNX-300).
- **Provider-neutral billing foundation** (FORNX-46, landed under
  fornax-cloud's own v0.0.3 branch prefix per its actual PR history —
  see `release/v0.0.2-candidate-manifest.json`'s notes and
  `docs/adr/0003-billing-entitlement-and-provider-boundary.md`): sandbox-only
  Dodo checkout/webhook/entitlement, not part of v0.0.2's shipped scope.

## What this is not

- **Not self-service today via SSO.** SSO is the intended primary sign-in
  path (FORNX-111/FORNX-309) but has no live Keycloak instance in this
  environment yet; the documented break-glass device-credential path is
  the only one exercised live so far. Device registration itself is
  genuinely public and self-service (`POST /v1/devices/register`,
  unauthenticated by design, create-only, 409-on-collision) — verified
  live against the real public Beta endpoint, not merely implemented.
- **No user/tenant/account system beyond device identity and
  session/org membership.** Confirmed by FORNX-151's implementer: device
  identity plus the session/org model added since are the identity
  primitives that ship in v0.0.2 — there is no separate "user account"
  concept beyond that.
