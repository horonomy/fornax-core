# Fornax v0.0.8 — Agent Epistemic Trust Kernel

**Status:** Real release. Readiness-gate verdict (FORNX-392): **CONTINUE,
with 3 explicitly disclosed carryovers** — this is not a clean pass, and
this document does not present it as one. Full gate evidence is recorded
in the FORNX-392 Jira ticket's evaluation comment; the summary below
reflects it honestly.

## What this is

Fornax v0.0.8 (Stage 9, epic FORNX-376, HVDL-15) turns Fornax's local
verification loop into a broader **agent epistemic trust kernel**: claims
carry explicit proof obligations, verification depth adapts to risk,
adversarial evidence is tested against a real attack corpus, and
evidence-backed trust state can move safely across agents via a
proof-carrying delegation protocol.

- **Epistemic Contracts** (FORNX-377/378) — a versioned claim-ontology and
  proof-obligation schema, with a satisfaction engine that evaluates
  whether real evidence actually meets a contract's requirements. A
  critical-obligation safety floor means a recommendation cannot reach
  `PROCEED` merely because aggregate evidence looks strong while a
  required obligation is unsatisfied.
- **Adaptive verification budgets** (FORNX-379) — verification effort
  scales with risk and existing evidence coverage instead of running
  either minimal checks or maximum-depth monitoring for everything.
  Destructive, credential-bearing, and unapproved-network actions remain
  refused regardless of budget or information value. Measured against
  minimal/maximal baselines **on synthetic fixtures only** — no real
  production workload benchmark exists yet.
- **Adversarial evidence corpus and authenticity hardening**
  (FORNX-380/381) — a documented threat model and a 26-fixture attack
  corpus (forged provenance, replay, capability spoofing, source
  amplification, and more), plus provenance hardening so an untrusted
  adapter cannot promote its own evidence to a higher trust class by
  setting payload metadata.
- **Self-integrity program** (FORNX-382/383) — a registry of 10 required
  trust-kernel invariants, each with an owning test; property-based tests
  generalizing several of them; a real 64-task concurrency stress test
  proving session isolation; and 4 Kani-verified bounded-model-checking
  proofs on receipt/delegation freshness logic.
- **Proof-carrying delegation and multi-agent shared-failure detection**
  (FORNX-384/385) — a delegation envelope that lets a parent agent verify
  a child agent's result from serialized bytes alone, without trusting its
  prose summary; and cross-agent dependency tracking so several agents
  sharing one underlying source cannot manufacture independent
  corroboration. A collusion hypothesis can never be emitted without
  actual supporting evidence — never from correlation alone.
- **Shadow execution** (FORNX-386) — isolated pre-flight verification for
  file-mutation and SQLite-migration changes, entirely local and
  disposable, with tested negative controls against path traversal,
  symlink escape, network access, and credential exposure.
- **Assurance cases** (FORNX-387) — a structured claim/argument/evidence/
  limitations model projected deterministically from contract-satisfaction
  results, resistant to prompt-injection-shaped evidence text gaining
  structural authority.
- **Meta-verification** (FORNX-388) — semantic judges and monitors are
  evaluated as fallible evidence sources, not roots of trust; an
  overconfident, factually-wrong monitor cannot force a verdict past a
  real contradiction.
- **Integrity incident intelligence** (FORNX-389) — a real incident-to-
  regression knowledge loop, extending existing audit/receipt primitives
  rather than building a second incident store.
- **Agent Evidence Protocol** (FORNX-391) — a versioned, publicly
  documented wire protocol with a genuinely independent second
  implementation (zero dependency on this repo's internal types) that
  exchanges and verifies a real proof-carrying delegation result.

**Federated calibration** (FORNX-390) is a completed research
investigation, not a shipped feature. Its own decision record concluded
**narrow/defer**: the aggregation mechanism works on synthetic data, but
no real multi-tenant demand and no real local reliability-observation
producer exist yet to justify shipping it.

## Readiness-gate verdict: CONTINUE, with 3 disclosed carryovers

FORNX-392 evaluated this candidate against 10 predeclared dimensions and
11 acceptance criteria. Most measurable dimensions passed on real,
independently-verified evidence. Three real gaps are carried forward
explicitly rather than resolved or hidden:

1. **A real 4-of-26 (≈15%) escape rate** on the frozen adversarial corpus.
   The four escapes: forged trust-class label authenticity, cross-claim
   evidence replay, and a known `O(n² log n)` scalability limitation in
   the evidence-independence module under very large evidence pools.
2. **No daemon/acquisition-identity binding yet** (FORNX-381's own
   disclosed AC2 gap) — cross-session attribution at that specific layer
   is not yet provably fail-closed.
3. **One of two targeted formal-verification proofs is unverified**
   (FORNX-383) — the acquisition-authorization state machine's Kani proof
   harnesses compile but hit a real CBMC memory limit, not a design flaw
   found. The other target (receipt/delegation freshness logic) has 4
   genuinely verified proofs.

None of this release's claims should be read as "adversarial evidence
cannot bypass Fornax" or "the trust kernel is formally verified" — neither
is true yet, and this document does not say otherwise.

## What this does not claim

- **Not an AI lie detector.** Fornax checks agent claims against captured
  evidence; it does not infer intent or detect deception from text alone.
- **No universal trust score.** Every verdict/state vocabulary in this
  release (satisfaction states, delegation outcomes, multi-agent signals,
  attack outcomes) is closed and never collapsed into a single number.
- **A delegation envelope's digest proves the message wasn't tampered
  with — it does not prove the underlying claim is semantically true.**
  Authenticity and truth are deliberately distinct throughout this
  release.
- **Kani's 4 verified proofs cover one state machine, not "formal
  verification of the trust kernel."**
- **Shadow execution's fidelity is exactly what its own metadata
  declares** — a passing shadow run is not equivalent to a production
  proof when dependencies differ.
- **The Agent Evidence Protocol is a real, independently-implementable
  spec — not a ratified or standards-body-endorsed protocol.**
- Multiple agents citing the same underlying source are never presented
  as independent confirmation by default (FORNX-385).

## Security

No unresolved Critical/High privacy/security/integrity blocker exists in
the code merged this release. The 3 carryovers above are real, disclosed
residual risk — not defects introduced by this release's own new code,
and not silently converted into a passing grade. See the FORNX-392 gate
evaluation for full per-dimension detail.

## Migration notes

All new surfaces (epistemic contracts, verification budgets, the
adversarial corpus, provenance hardening, self-integrity checks, shadow
execution, assurance cases, meta-verification, incident records, and the
protocol crates) are additive. No breaking changes to existing `Evidence`,
`Finding`, `Fusion`, causal/replay, or policy contracts from prior
releases.

## Known limitations

- No real human-adjudicated Gold Corpus data exists (FORNX-343 remains
  founder-paused for cost control) — no calibrated real-world accuracy
  claim is made anywhere in this release.
- Federated calibration (FORNX-390) is research-only; not shipped as a
  product feature.
- See "Readiness-gate verdict" above for the 3 items carried into future
  work.
