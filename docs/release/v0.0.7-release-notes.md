# Fornax v0.0.7 — Audit, SIEM & Data Governance

**Status:** Real, complete release. Full QA/security evidence:
[`docs/release/v0.0.7-qa-signoff.md`](v0.0.7-qa-signoff.md). Candidate
manifest: [`release/v0.0.7-candidate-manifest.json`](../../release/v0.0.7-candidate-manifest.json).

## What this is

Fornax v0.0.7 adds tamper-evident audit and compliance infrastructure on
top of v0.0.6's enterprise policy layer:

- **Tamper-evident local audit ledger** — hash-chained entries with
  independent divergence checks for missing sequences, relinked previous
  hashes, and hash mismatches, plus truncated-tail detection.
- **Checkpoint witnessing** — periodic submission to the cloud that
  honestly reports its own divergence rather than suppressing it.
- **Compliance reporting** — surfaces real ledger-integrity status
  end-to-end.
- **Bounded, resumable retention sweeps** — never process an unbounded
  backlog in a single call.

## This is a real, complete release

Stage 6c's release gate — [FORNX-323](https://lightning-dust-mite.atlassian.net/browse/FORNX-323),
"[Audit Integrity Gate]" — is genuinely earned, the same standard as
v0.0.6's FORNX-124. It was closed with a real adversarial test suite
spanning both fornax-core and fornax-cloud, which found and fixed a real
cross-repo TOCTOU race in fornax-cloud's tenant-data-deletion legal-hold
check (already shipped in fornax-cloud v0.0.3). There is no unfabricatable
external-evidence gap here.

## Security

A fresh, independent review — separate from FORNX-323's own adversarial
testing — covered SQL-injection re-verification of every manual safety
assertion introduced by a dependency upgrade, audit-log tamper-evidence,
retention/deletion correctness, compliance-report accuracy, and
checkpoint-submission resource bounds. **Zero findings.**
`risk_class: TRUST_BOUNDARY` reflects that this ships the audit/compliance
integrity guarantee downstream trust and legal/compliance claims depend on,
not any defect. See [`docs/release/v0.0.7-qa-signoff.md`](v0.0.7-qa-signoff.md)
for full detail.

## Architectural note

fornax-core's local retention is a purely on-device data-lifecycle
boundary and does not implement a `legal_hold` concept — that control
exists separately in fornax-cloud, scoped to centrally-stored tenant data.
This is an intentional architectural boundary, not a gap.

## Cross-repo pairing

This release pairs with
[fornax-cloud v0.0.3](https://github.com/horonomy/fornax-cloud/releases/tag/v0.0.3%2Bcorrected.f1b293c),
which ships the cloud-side audit checkpoint receipt, SIEM delivery, and the
legal-hold fix this release's own gate testing helped surface.

## Migration notes

No breaking changes to existing `Evidence`, `Finding`, `Fusion`, causal/
replay, or policy contracts. All new surfaces (audit ledger, checkpoints,
compliance reports, retention sweeps) are additive.
